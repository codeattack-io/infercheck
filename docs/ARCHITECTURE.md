# Architecture

Reference for how InferCheck is put together. Product description and contribution flow: [README](../README.md). Visual design: [DESIGN.md](DESIGN.md).

## Components

| Component        | Where                                     | What it does                                                                                                      |
| ---------------- | ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Web app          | `src/app/`                                | Next.js 16 App Router with `cacheComponents: true`, deployed on Vercel                                            |
| i18n             | `src/i18n/`, `src/proxy.ts`, `messages/`  | next-intl, locales `en` and `de`, `localePrefix: "always"`; `proxy.ts` is the locale routing middleware           |
| Provider data    | `data/providers/{slug}.json`              | One file per provider, validated by the Zod schemas in `data/schema.ts`; read from disk by `src/lib/providers.ts` |
| Model catalog    | Neon Postgres, `src/db/schema.ts`         | Tables `models` and `sync_log`, accessed with Drizzle; read by `src/lib/models.ts`, written by `src/lib/sync/`    |
| Migrations       | `drizzle/`                                | SQL generated by `drizzle-kit generate`, applied by `drizzle-kit migrate`                                         |
| Sync             | `src/lib/sync/`, `scripts/sync-models.ts` | Adapters that fetch model lists, upsert logic, orchestration (`runSync`)                                          |
| Cron route       | `src/app/api/cron/sync-models/route.ts`   | Runs `runSync` for the nightly Vercel Cron job and invalidates the model cache                                    |
| Error monitoring | `src/instrumentation*.ts`                 | `@sentry/nextjs` pointed at a Sentry-protocol endpoint (GlitchTip); inactive when no DSN is set                   |
| Analytics        | `src/app/[locale]/layout.tsx`             | Script served through the `/stats` rewrite in `next.config.ts`                                                    |

Routes under `src/app/[locale]/`: `/` (model table), `/providers`, `/provider/[slug]`, `/model/[id]`, `/about`, `/imprint`, `/privacy`, plus `opengraph-image`. `src/app/sitemap.ts` lists all of them with `hreflang` alternates.

## Provider data

- Two shapes, both in `data/schema.ts`: `ProviderSchema` (full compliance profile) and `ProviderStubSchema` (`compliance: null`, `verifiedBy: "stub"`).
- `src/lib/providers.ts` parses each file with the full schema first, then the stub schema. Files that match neither are skipped at runtime; `bun run validate` fails on them.
- `translations.{locale}` holds locale-specific overrides for free-text fields only. `getLocalizedProvider` overlays them and falls back to English per field.
- `src/lib/compliance.ts` derives the compliance tier (`compliant`, `partial`, `noncompliant`, `unverified`) and the filter presets from the structured fields. It has no server-only imports and is shared with client components.
- `src/lib/verification.ts` maps `verifiedBy` to the label shown on the site: `stub` shows nothing, `ai_draft` shows "AI draft · date", any other value (a person's handle) shows "Verified date".

## Model catalog

`models` has one row per `(id, provider_slug)`. Relevant columns:

- `canonical_model_id`: provider-independent id from `deriveCanonicalModelId` (`src/lib/sync/utils.ts`); groups offers of one model across providers and is the `/model/[id]` route key.
- `input_price_per_m_tokens`, `output_price_per_m_tokens`, `price_currency`: `numeric(12,6)` prices per 1M tokens and their ISO 4217 code.
- The UI formats each price with the row's own `price_currency`; the model page's JSON-LD offers carry it as `priceCurrency`.
- `is_native_model`: `false` when the provider hosts a third-party model (shown as a gateway pill and notice).
- `sync_source`: `openrouter`, `provider_api` or `manual`.
- `is_active`: rows are deactivated, never deleted.

`sync_log` gets one row per adapter per run with counts and the error text.

## Sync data flow

```
Vercel Cron (vercel.json, 02:00 UTC daily)
  → GET /api/cron/sync-models        Authorization: Bearer $CRON_SECRET
    → runSync()                      src/lib/sync/run.ts
      → for each adapter in PROVIDER_ADAPTERS:
          fetch rows → group by provider slug → upsertModels per slug → sync_log row
    → failures → Sentry + HTTP 500
    → revalidateTag("models", "max")
```

`bun run sync:models` calls the same `runSync`; `--dry-run` skips every database access.

**Route behaviour**

- `CRON_SECRET` unset → 500, wrong bearer token → 401, unknown `?provider=` → 400.
- All adapters succeed → `200 {ok: true}`.
- Any adapter failed → each failure goes to `Sentry.captureException` (tags `job: sync-models`, `adapter`), Sentry is flushed, and the response is `500` with `failedAdapters`, so Vercel marks the cron run failed.
- `revalidateTag("models", "max")` runs unless every selected adapter failed.
- `maxDuration` is 60 seconds.

**Adapters** (`src/lib/sync/adapters/`)

| Key                     | Source                                                              | Without credentials        |
| ----------------------- | ------------------------------------------------------------------- | -------------------------- |
| `openrouter`            | OpenRouter catalog and per-model endpoints API                      | none needed                |
| `mistral`               | `api.eu.mistral.ai/v1/models`, `MISTRAL_API_KEY`, static price seed | returns no rows            |
| `scaleway`              | public Scaleway product catalog (models and prices)                 | none needed                |
| `stackit`               | Model Serving API with `STACKIT_API_KEY`, static price seed         | static list in the adapter |
| `berget-ai`             | public `api.berget.ai/v1/models`                                    | none needed                |
| `ovhcloud-ai-endpoints` | static list in the adapter                                          | none needed                |
| `amazon-bedrock`        | AWS SDK model and inference-profile listing, static price seed      | returns no rows            |
| `aleph-alpha`           | none; the adapter returns no rows                                   | —                          |

An adapter that returns no rows changes nothing in the database.

**Per-adapter processing**

1. The adapter returns `ModelRow[]`. Prices pass through `toPricePerMTokens`: missing, non-finite, negative, or above 10,000 per 1M tokens become `null` ("price unknown"). Each row carries its `priceCurrency`: `USD`, except Berget AI, whose API reports the currency (default `EUR`), and Scaleway, STACKIT and OVHcloud, whose prices are `EUR`.
2. Rows are grouped by `providerSlug` and written by `upsertModels` in batches of 100. If a batch fails, its rows are retried one by one; rows that still fail are collected and make the adapter fail after the others were written.
3. A thrown error in one adapter is recorded in `failures` and `sync_log`; the remaining adapters still run.

**Deactivation rules** (`src/lib/sync/db.ts`)

- After upserting a provider, active rows of that provider whose id the adapter did not list are set inactive.
- Ownership is split in two: OpenRouter rows (`sync_source = 'openrouter'`) are only deactivated by the `openrouter` adapter, all other rows only by the provider adapters. An OpenRouter row never overwrites an existing provider-adapter row with the same `(id, provider_slug)`.
- After the OpenRouter run, active OpenRouter rows of providers the adapter emitted no row for in this run are set inactive (`deactivateUnlistedProviders`).

### OpenRouter attribution

`src/lib/sync/adapters/openrouter.ts` attributes a model to the host that serves it, not to the model's author prefix.

1. Fetch `https://openrouter.ai/api/v1/models`; drop variant ids containing `:` and ids starting with `~`.
2. For each model fetch `/api/v1/models/{id}/endpoints` (concurrency 4, up to 3 attempts with backoff, honouring `Retry-After`). If more than 5% of the endpoint requests fail, the adapter fails; otherwise the failures are logged.
3. Each endpoint has a tag whose first segment names the serving host. Only hosts listed in `OPENROUTER_HOSTS` are used, and that map is limited to hosts whose OpenRouter prices match their own price list. Endpoints of all other hosts are excluded. `OPENROUTER_HOSTS` maps the host to a provider slug and can refine it:
   - `authors`: author prefixes the host serves as its own models (`is_native_model = true`).
   - `slugByAuthor`: a different provider slug for a given author, e.g. Anthropic models on Google Vertex belong to `vertex-anthropic`.
   - `servesAuthors`: restricts the host to these authors.
4. Endpoints are filtered and ranked by region: endpoints with a service tier, a non-standard tier segment, or a non-EU region segment are dropped. EU-scoped endpoints rank 0, global or unscoped endpoints rank 1.
5. Per model and host the best endpoint wins: lowest rank, then the quantisation most used by that host, then the lowest input price, then the tag. One row per `(model, host)` results.
6. Prices and context length come from the selected endpoint, converted from per-token to per 1M tokens, currency `USD`. A zero price (per-request or per-image pricing) becomes `null`.

Providers served by their own adapter (Mistral, Scaleway, Bedrock, …) are deliberately absent from `OPENROUTER_HOSTS`.

## Caching and freshness

- Every read in `src/lib/models.ts` is a `"use cache"` function with `cacheLife("hours")` (revalidate after 1 hour, expire after 1 day) and `cacheTag("models")`.
- The cron route marks tag `models` stale after a sync (`revalidateTag("models", "max")`); the next request regenerates the pages. `bun run sync:models` run from a shell does not invalidate the cache, so those changes appear after the `cacheLife` revalidation.
- `generateStaticParams` and the sitemap read the model table at build time, so `next build` needs a reachable database.
- The home page ships the full model list to the browser. `ModelBrowser` and `ModelTable` search with Fuse.js, filter and sort on the client, and keep the state in the URL query string through the History API (`src/lib/url-state.ts`). Changing it does not request the server.

## Environments and variables

Names only; values live in `.env.local` (never committed), the Vercel project, and GitHub secrets.

| Variable                                                          | Read by                          | Notes                                                                             |
| ----------------------------------------------------------------- | -------------------------------- | --------------------------------------------------------------------------------- |
| `DATABASE_URL`                                                    | app, sync, `drizzle.config.ts`   | Required. Neon connection string                                                  |
| `CRON_SECRET`                                                     | cron route                       | Required in production; the route rejects every request without it                |
| `MISTRAL_API_KEY`, `STACKIT_API_KEY`                              | sync adapters                    | Optional; see the adapter table                                                   |
| `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_REGION`        | Bedrock adapter                  | Optional; `AWS_REGION` defaults to `eu-central-1`                                 |
| `OPENAI_API_KEY`                                                  | research and translate scripts   | Only for those scripts                                                            |
| `GITHUB_TOKEN`                                                    | `scripts/import-models-dev.ts`   | Optional; raises the GitHub API rate limit                                        |
| `NEXT_PUBLIC_GITHUB_REPO_URL`                                     | footer, about page, report links | Defaults to a placeholder when unset                                              |
| `SENTRY_DSN`, `NEXT_PUBLIC_SENTRY_DSN`                            | instrumentation                  | Optional; unset disables error monitoring. The public one is needed at build time |
| `SENTRY_URL`, `SENTRY_AUTH_TOKEN`, `SENTRY_ORG`, `SENTRY_PROJECT` | `next.config.ts`                 | Source map upload; all four must be set or the upload is skipped                  |

GitHub Actions secrets used by the workflows: `DATABASE_URL` (deploy, in the `production` environment), `DATABASE_URL_DEV` (CI build), `VERCEL_TOKEN`, `VERCEL_ORG_ID`, `VERCEL_PROJECT_ID`, `RENOVATE_APP_PRIVATE_KEY`; repository variable `RENOVATE_APP_CLIENT_ID`.

Commands that write to the database (`sync:models` without `--dry-run`, `db:migrate`) change whatever `DATABASE_URL` points at.

## CI and deploy

**`ci.yml`** runs on pull requests only. Bun is pinned to one version.

- `check`: `prettier --check .`, `eslint --max-warnings=0`, `tsc --noEmit`, `bun run validate`.
- `build`: `bun run build` with `DATABASE_URL` set from `DATABASE_URL_DEV`. Skipped for pull requests from forks, which get no secrets.

**`deploy.yml`** runs on pushes to `main` and on manual dispatch, with runs queued one after another instead of cancelled:

1. `migrate`: `bun run db:migrate` against the production database (`environment: production`).
2. `deploy`: `vercel deploy --prod`, only after `migrate` succeeded.

**`renovate.yml`** runs self-hosted Renovate every Monday 07:00 UTC, on edits of the dependency dashboard issue or Renovate pull requests, and on manual dispatch. It authenticates as a GitHub App (variable `RENOVATE_APP_CLIENT_ID`, secret `RENOVATE_APP_PRIVATE_KEY`). `.github/renovate.json` configures it:

- Patch, minor, pin and digest updates automerge once checks pass; major updates need manual review.
- `minimumReleaseAge` of 3 days; lockfile maintenance and vulnerability alerts automerge.
- Grouping: all patch updates, Next.js/React, Drizzle, AI SDK, Sentry, TypeScript and types.
- Version caps for `eslint` (below 10), `typescript` (below 6.1) and `dotenv-expand`, each with its reason in the rule.
